# Как собрана карта Ленинградской области

Записано, чтобы сборку можно было повторить через год на чистой машине.
Все числа ниже сверены с заголовком готового файла, а не написаны по памяти.

## Что получилось

| Свойство | Значение |
|---|---|
| Файл | `LENOBL.map` |
| Размер | 183 983 843 байта |
| Формат | Mapsforge binary, версия файла 3, размер плитки 256 |
| Границы | широта 58,35–61,35, долгота 27,70–35,75 |
| Собрано | mapsforge-map-writer 0.25.0 под osmosis 0.49.2 |
| SHA-256 | `096a11c160d05f75b11f6929c3c23b52fba1579f1f3253539b7461fdaf4870bd` |

Горизонталей в этой карте нет — намеренно. Приложение берёт высоты
из файлов SRTM (.hgt) и само считает по ним затенение рельефа, поэтому
горизонтали в карте только раздули бы файл вдвое.

## Что нужно для повторения

- Java 17, osmosis 0.49.2 с подключаемым модулем mapsforge-map-writer 0.25.0
- Не меньше 3 ГБ памяти для Java: `JAVACMD_OPTIONS=-Xmx3G`
- Выгрузка Северо-Западного федерального округа с
  https://download.geofabrik.de/russia/northwestern-fed-district.html
- Файл соответствия тегов `tag-mapping-taiga.xml` из репозитория кода

## Порядок

1. Вырезать область из окружной выгрузки:

```
osmium extract -s smart -b 27.70,58.35,35.75,61.35 \
  northwestern-fed-district-latest.osm.pbf -o lenobl.osm.pbf --overwrite
```

2. Собрать карту:

```
JAVACMD_OPTIONS=-Xmx3G osmosis \
  --rb file=lenobl.osm.pbf \
  --mapfile-writer file=LENOBL.map \
    type=hd \
    bbox=58.35,27.70,61.35,35.75 \
    tag-conf-file=tag-mapping-taiga.xml
```

Порядок чисел в `-b` у osmium и в `bbox=` у osmosis разный — это не опечатка.
У osmium это запад,юг,восток,север, у osmosis — юг,запад,север,восток.
Перепутанные местами числа дают пустую карту без единой ошибки в логе.

Сборка идёт около трёх часов и требует свободного места примерно вдвое
больше итогового файла. Параллельно с ней ничего тяжёлого запускать нельзя:
при нехватке памяти osmosis не падает сразу, а тихо умирает через час.

## Чем наш tag-mapping отличается от стандартного

Дополнительно сохраняются теги, без которых приложение не может считать
проходимость и не может показать вырубки:

- `natural=wetland` и подтип `wetland=*` — болота по видам
- `leaf_type=*` — хвойный, лиственный или смешанный лес
- `man_made=cutline` — просеки
- `landuse=forest` вместе с `landcover=trees`
- `highway=track` с `tracktype=*` — лесные дороги по проходимости

Стандартный tag-mapping их выбрасывает, и карта получается красивой,
но бесполезной для расчёта пути.
